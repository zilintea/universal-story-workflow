## 评估方法
逐条对照手册的方法与本仓库现有规则，分三类：已覆盖（不用改）、新增（本次补进）、
不适用（手册的工具专属做法，本仓库的生成管线用不上，只记结论不抄做法）。
手册的提示词原文不抄进仓库：所有新增内容都按本仓库自己的字段和语言重写，只取方法。

## 已覆盖（手册有的，本仓库已有，不用改）
| 手册的方法 | 本仓库已有的对应物 |
|---|---|
| 文字先定，错挡在花钱之前 | 关卡 1–4：文字 → 故事板 → 试点（最难的一段先拍）→ 批量；审计不过不烧积分 |
| 首尾帧锁定，尾帧即下镜首帧 | SHOT_LANGUAGE 首尾帧锁定 SOP：上一段尾帧当参考图，`Continue from this exact frame.` |
| 每段验收抽帧 | 每段抽 0.5s / 5s / 9.9s 三帧核对，任一项不符只重做该段 |
| 逻辑追问、主题一句话 | logic_audit：因果连续、无“刚好出现”的人、主题一句话可复述、外人复述测试 |
| 镜头卡、换角度、30 度、180 度轴线、动作匹配、视线匹配 | SHOT_LANGUAGE 14 字段短码 + EDITING_STANDARDS + edit_check.py |
| 一个镜头只做一件事 | shotcard_audit：一个镜头只做一件事；起幅落幅都能独立成图 |
| 画面里要有东西在动 | SHOT_LANGUAGE：env 字段，不写环境动态画面像 PPT |
| 三视图定型 | CHARACTER_CONSISTENCY + 三视图硬门 v3.1：缺文件不进故事板 |
| 文化锚点、语言锁定 | CULTURE_ANCHORS + LANGUAGE_LOCK（v3.3）：画面内文字语言跟目标语言走 |
| 先拍最难的镜头再批量 | 关卡 3 试点：通常最难的一段先拍，通过了才批量 |
| 失败不重复原请求 | VIDEO_DELIVERY：改用更安全的讲法重拍该段，并说明改法 |

## 新增（本次 v3.7 补进）
1. **七段式视频提示词模板**（templates/video_prompt_7seg.md）：取代 SHOT_LANGUAGE 的 6 段拼装。
   新增的两段是“逐秒”（0–0.2 秒静止等于首帧、最后 0.3 秒停住等于尾帧）和“声音”（只写看得见原因的
   声音，人物不说话）；其余五段按本仓库字段重写：画风、镜头、构图与配色、人物、约束。
2. **镜头卡加两个字段**（14 → 16）：`moving`（这镜什么在动：摄影机/焦点/光线/飘过物/小动作，
   至少一样；该静的地方静）和 `move_reason`（运镜的理由：跟人或物走 / 推近给特写 / 拉远，三选一）。
3. **机位多样性硬规则**：全片平视正面最多两次，其余用俯拍、仰拍、从背后、过肩、透过东西拍；
   景别全身/半身/特写轮换，不连着三镜同一景别（后者已有，前者新增）。
4. **黄金比例构图**：人物头或眼睛落在画面横向约 38% 或 62% 处，不放正中间。
5. **配色表 + 黑白检查**：画第一张图之前定配色，每场一张色表；色块草图转黑白，人和背景
   分不开即明暗对比不够，重调配色。
6. **开头抓人**：最抓眼球的画面放前面，文字稿写清第几秒出现什么；logic_audit 加一项。
7. **旁人反应三段式**：每个包袱/转折分三段写——问题 → 主角怎么解决 → 旁人什么反应；
   反应要有先后，绝不同时做同一个动作；细节要真（吃惊时身体往后缩）。
8. **AI 弱点清单（写故事时就避开）**：人物交叉、手拿小东西、文字、镜子与倒影、左右不对称特征、
   一镜内换光、一人连做三个动作、俯拍看不到脸、配角太多。进 story_text_output 模板与 logic_audit。
9. **片段式默认**：故事结构默认片段式（每镜不用接戏，最稳）；连贯式只在用户点名时用，接戏逐对核对。
10. **首尾帧 SOP 补四条**：先画内容最多的那张（一般是尾帧），再由它改出首帧，保证机位构图一致；
    同地点同机位的镜直接在前一张图上改；动作要用的东西首帧里必须有；旁人反应首帧里提前摆好
    （前面做事、后面的人脸朝镜头）；提交前检查首尾帧尺寸一致、宽高比正确。
11. **模型易错对照表**（docs/MODEL_ERROR_TABLE.md）：同时动作、歧义句、数量变化、“不要……”写法
    失效、道具自带用法、凭空出现、瞬间移动、雨/帽子/纹身拍丢、动作太多、时间对不上、推得不明显、
    嘴自己动、音乐混入、尾帧跳变、首帧过锐、越拍越暗——每条给本仓库的写法。
12. **提交前新视角审计**（checklists/presubmit_audit.md）：生成视频花钱之前，另开一个 fresh 视角
    只读材料（提示词、首尾帧、设定图、分镜表、配色规则），只挑错不改文件，逐项核对后只写
    “通过”或“不通过”；不通过逐条列改法，改完再审。
13. **全片复核**（checklists/final_review.md）：成片后另开 fresh 视角，只给成片不给结论；先写看懂的
    故事再列看不懂的地方；逐镜查重复动作、道具数量、穿帮、夹帧、颜色跳变、字幕；明确写出查不到
    的东西（动态手感、声音）；每条写时间、帧号、问题，分“硬伤”和“小问题”。
14. **先修后重拍**（VIDEO_DELIVERY）：视频有问题先问三句——能不能剪掉（只坏开头或结尾几帧）？
    能不能用代码修？修不了才重拍该镜，且先改提示词或首尾帧再拍；旧片段不删，留着最后一起挑。
15. **每段按首帧校色**（VIDEO_DELIVERY）：视频越拍越暗/越冷时，每段按自己的首帧把颜色调回来。
16. **参考片逐帧量**（SHOT_LANGUAGE）：镜头语言写不清时，找参考片逐帧看，量出机位、进出画比例再模仿；
    没参考片才按规则自己构思。

## 不适用（手册的工具专属做法，不抄）
- Claude/Codex/Seedance 的分工与调用方式、Seedance 接口地址与价格、720p 计价、四线程
  （主做/审核/监督/代理）的人员配置：本仓库的生成由 Muse 直接做，不走这套工具链。
  只取其背后的原则：错误挡在花钱之前、提交前 fresh 视角审、修在先重拍在后。
- BT.601 解码、BT.709 交付、lanczos 放大、半帧快门转场：Seedance 出片的后期参数；
  本仓库只取“交付前统一分辨率、每段按首帧校色”这一条，其余不写死。
- “不充值、不买额度”：计费规则是手册作者自己的预算纪律，不是提示词数据，不进技能。
