# Token / 额度预算（v1.9 新增，省 token 是硬规则）

> 教训（用户 2026-11-05）：一个视频在豆包上测试，一个月的用量一次就用完了。
> 原因：每集先出故事板图，再出 N 段视频，每段提示词都把人物、场景、
> 风格重写一遍，错一段就整批重做。
> 本文件把省 token 写成硬规则，不是建议。

## 硬规则（四条）

1. **先试点，再批量**：每集先只做 1 段试点（通常是最难的一段），
   镜头卡和首尾帧都对了，才做剩下 N−1 段（N = D ÷ 10）。试点不过，不烧后面 N−1 段。
2. **只传编号，不传全文**：人物、场景、风格、镜头卡只写一次，
   之后每段只写编号，如 `人物 C1、场景 S1、风格 ghibli、镜头 MCU`，
   不重复写描述。锁定表另存，见 `docs/TOKEN_OPTIMIZATION.md`。
3. **只重做错的那一段**：哪段漂了只重做哪段，不整批重做；
   故事板先出文字版，文字通过了再出图，图不通过只改那一格。
4. **镜头卡用短码**：景别、机位、运镜、构图都用短码
   （MCU / EL / STATIC / THIRDS），不用写整句英文。
   长提示词不是更专业，是更烧。

## 预算表（每集，按参数 D 算，供用户决策前参考）

| 项 | 预算 | 说明 |
|---|---|---|
| 文字稿 | 1 次 | 含世界地图、镜头卡、旁白、审计；文字没通过不进视频 |
| 故事板文字版 | 1 次 | G 格文字卡（G = N × 3） |
| 故事板图 | 1 次 | 只出 G 格构图参考图（D=60 秒时分两张 9 格），不作视频参考图 |
| 试点视频 | 1 段 | 1 段 × 10 秒 |
| 批量视频 | N−1 段（试点 1 段 + 批量 N−1 段，N = D ÷ 10） | 试点通过后才做；每段约 10 秒 |
| 重做 | 每段 ≤2 次 | 两次不过改拍法，不无限重做 |
| 音频 / 字幕 | 各 1 次 | 文本，不烧视频额度 |

## 平台额度提醒

- 视频生成按段计费/计额度，不按镜计；手册里的 16–25 镜是分镜密度，
  不是生成段数，不强制每镜单独生成一段。
- 换平台（如豆包）前，先报该平台的单段成本和本集总段数，用户点头再烧。
- 任何要烧积分/额度的生产计划，先回答哪个最好、哪个最烧，未经确认不动手。
