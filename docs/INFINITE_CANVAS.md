# 无限画布故事板（v3.16 · 生成前输出）

## 9 宫格的局限

- 一张图 1920×1280、3 列、每张最多 9 格；超 9 格就分多张。
  12 镜的集子要分两张，每格约 640×427，看不清细节。
- 格子是平面图里的一个小方块：点不开，没有链接，没有状态，
  没法指着某一格说“重做这格”，只能用语言描述“段 2 尾帧”“第 8 格”，
  一描述就错位，重做时常改错格。
- 故事板是构图参考，不是人物/物品参考，格子图不能复用为视频参考图；
  平面图把构图和参考混在一起，越用越乱。

## v3.12 的缺口（2026-11-15 用户提）

v3.12 的画布只在视频生成后才完整：节点内容是“本镜抽帧图（视频生成后补）”，
规则 2 要求“视频生成后，每段的首/中/尾三帧必须补进对应节点”。
也就是说，画布要等视频烧完积分才出现——用户想在生成前调整某一镜的运镜、
景别、动作时，没有东西可点、可改。生成前的画布是缺的，这就是要修的功能。

## v3.16 的修法：画布在生成前输出（关卡 2.5）

画布分两段交付，生成前那段是主交付：

### 生成前（关卡 2.5，视频生成之前必须输出）

- **输出时机：** 关卡 2（故事板文字版 + 画布图版）通过后、第 7 步视频生成之前。
  画布没输出、用户没确认，不进第 7 步——试点也不行。
- **节点内容（生成前就有）：** 稳定编号与链接（例如 `#seg2-shot3`）、镜头卡短码
  （景别 / 机位 / 运镜 / 动作起—中—止）、参考图（主画布格裁剪 / 三视图 /
  上一段尾帧占位）、旁白/对话时间戳、状态。
- **节点状态（生成前）：** 待确认 / 已确认 / 待调整。
  用户在画布上点开节点就能改：换运镜、换景别、改动作、改首尾帧；
  改完节点状态回“待确认”，再确认一次才变“已确认”。
- **只有“已确认”的节点进视频生成。** 待调整的节点不生成、不烧积分。
  试点段 = 第一批已确认的节点，不是“先烧一段看看”。

### 生成后（补全节点）

- 每段生成完，首/中/尾三帧与视频文件链接补进对应节点，节点状态改为
  通过 / 偏差 / 待重做（带偏差说明），才算完整；没补抽帧的节点不进批量验收。
- **重制入口不变：** 每个节点一个“重制此镜”按钮，点开即得该镜的重制指令：
  镜号、当前问题、改法、参考图（主画布格裁剪 / 上一段尾帧），
  复制后发给执行方即可重做，不用用户再描述是哪一格。
  重做只换该节点，不动其他节点；新版进节点当 v2，旧版留档。

### 其他

- **工作流链接。** 每个节点链回它的 workflow 来源：文字稿行、故事板条目、
  视频文件、音频、字幕；改了哪一格，来源一查就知道。
- **总览缩略图。** 9 宫格平面图可附在画布顶部当总览，不当交付物。
- **画布顶栏。** 写全片人数、画幅、主画布版本号；主画布改版时画布顶栏同步升版。
- **故事 JSON 字段。** 画布文件路径写进 `infinite_canvas` 字段；
  `scripts/check_story.py` 查文件存在（有字段时必填且文件必须存在，
  无字段时跳过，旧稿不受影响）。

## 规则

0. 画布在视频生成前输出；未输出画布、用户未确认，不进第 7 步（试点也不行）。
1. 关卡 2 通过的是节点内容（每镜的动作、地点、物品状态），不是平面图的美观。
2. 视频生成后，每段的首/中/尾三帧必须补进对应节点，节点才算完整；
   没补抽帧的节点不进批量验收。
3. 节点编号终身不变：重做只升版本号（v1→v2），不改编号、不删旧版。
4. 画布顶栏写全片人数、画幅、主画布版本号；主画布改版时画布顶栏同步升版。
5. 只有“已确认”的节点进视频生成；待调整的节点不生成、不烧积分。
