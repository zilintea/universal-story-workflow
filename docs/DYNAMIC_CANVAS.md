# 动态画布：故事板格数按实际镜数走（v3.2）

## 问题

格数一直是死公式 `G = N × 3`：30 秒 9 格，60 秒 18 格，分两张 9 格。
这个公式是错的——故事板每格的意义是一个动作、一个地点（见 `docs/CANVAS.md`），
也就是一个不同的构图。一个场景里全是对话、没有转场，构图根本没变，
硬画 3 格就是同一张图画三遍，纯烧 token。

## 评估（按本技能自己的原则）

1. **画布的本意。** 故事板每格 = 一个动作、一个地点。格数应该跟着镜数走，
   镜数跟着转场走。死公式违背了画布的本意。
2. **Token 预算。** `docs/TOKEN_BUDGET.md` 的原则是只花该花的钱：
   只传编号、只重做错段、先试点再批量。60 秒对话为主的集子，死公式 18 格（两张图），
   动态评估约 8 格（一张图），省一半以上的故事板 token。
3. **已验证的集子。** 《井边的红灯笼》第 3 段有 3 个不同构图（跪下还鞋 / 灯笼飘远 / 天亮新坟），
   3 格合理；一段纯对话、机位不动的戏，1 格就够。格数看内容，不看时长。

## 规则

- **G = 实际镜数。** 先定镜表（分镜），镜数是多少，格数就是多少；一格一镜，一一对应。
- **每段 1–3 格。** 每段至少 1 格（每段都要在故事板上出现）；每段至多 3 格。
  一段纯对话、无转场、机位不动时，该段只画 1 格，不硬凑 3 格。
- **分张规则。** 格数 ≤9 时一张图；超过 9 格时，每张最多 9 格，分多张出。
- **不追溯。** v3.2 之前的集子（已按 `G = N × 3` 出过故事板的）不动，只管新活。

## 脚本

`scripts/check_shotcard.py` 查：

- 镜头卡可带可选字段 `segment`（第几段，从 1 开始）；不带时按旧约定推断（每 3 镜一段），旧稿不受影响。
- 同一段里，两镜的景别 + 机位 + 环境 + 出场人物 + 动作起止完全相同，即不通过：
  同一个瞬间画了两遍，合并为 1 格。这是本集省 token 的硬检查。
  正反打不算重复：动作不同，构图就不同。
- 输出格数 `G = 镜数` 和每段格数，供核对。
- 连续同景别 ≤2 的旧规则同步修正：只看同一主角。反打轮流换人时，同景别连拍不算单调；
  同一主角连续 3 镜同景别才不通过。
